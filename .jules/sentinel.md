## 2024-05-16 - [Firewall Whitelist Bypass & Fail-Open Filter]
**Vulnerability:** The `Firewall` class in `adapt_agent/security/firewall.py` had a logic flow that checked allowed patterns before blocked patterns, effectively permitting malicious content if it also contained a whitelisted phrase. Additionally, custom filters were "fail-open" (uncaught errors allowed input through) and the allowed patterns acted as an optional check rather than a strict whitelist.
**Learning:** Checking allowed patterns first creates a direct bypass for blocked patterns if an attacker embeds a whitelisted string in their malicious payload. Custom security controls must also default to failing closed, otherwise a malformed input that crashes a filter will proceed uninspected.
**Prevention:** Always enforce a deny-first logic (blocked patterns -> custom filters -> allowed patterns). Catch exceptions in custom filters, log them properly, and return a block. Ensure that defining a whitelist enforces strict adherence unless the whitelist is explicitly empty.
