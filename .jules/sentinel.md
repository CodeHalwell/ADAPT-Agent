## 2024-04-14 - Firewall Validation Bypass and Fail-Open Vulnerability
**Vulnerability:** The `check_input` method in `adapt_agent/security/firewall.py` checked allowed patterns (whitelist) *before* blocked patterns or custom filters. This allowed a malicious input to completely bypass security blocks simply by matching any pattern in the whitelist. Additionally, the custom filters implemented a fail-open design: if an exception occurred during a custom filter evaluation, the error was ignored (and printed to stdout, exposing potential stack traces/details), and the input was allowed through. Furthermore, the whitelist wasn't strict; if a whitelist existed but wasn't matched, the input was still allowed.
**Learning:** Checking whitelists before blacklists can inadvertently permit malicious payloads if the payload satisfies the whitelist condition (e.g., contains a benign word). Security controls must fail closed when errors occur, otherwise an attacker could craft input designed to crash the validation filter and bypass it. Logging should use the standard `logging` module rather than `print` to avoid unintentional information leakage.
**Prevention:** Always check blocked patterns and perform custom filtering before checking allowed patterns. Ensure custom security checks fail securely (block access) if they encounter an exception. Enforce strict whitelisting: if allowed patterns are configured, input must match at least one of them to be permitted. Use `logging.error` to safely log security events instead of `print`.
